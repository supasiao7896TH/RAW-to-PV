# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

RAW → PV Calculator — a DCS Yokogawa tag converter (repo name on GitHub: `RAW-to-PV`). Converts a RAW% signal (0-100) into the real Process Variable using:

```
PV = SVL + (RAW% / 100) × (SVH − SVL)
```

Three features live in one page: Calculator (single conversion), Tag Library (CRUD store of tags with SVH/SVL/unit, CSV import/export), and Batch Mode (convert a list of RAW% values against one tag's span at once).

## Architecture

Plain HTML/CSS/JS PWA — **no build step, no bundler, no package.json, no framework**. Every file is served as-is.

- `index.html` — all markup for the 3 tabs (`#calculator`, `#library`, `#batch`), the add/edit-tag modal, the floating minus-bar, and the toast element.
- `js/app.js` — single flat script (not modularized), loaded directly via `<script src="js/app.js">`. Contains:
  - `calcPV(rawPct, svh, svl)` — the core formula.
  - Persistence via plain `localStorage` under key `dcs_tag_library` (`loadTags()`/`saveTags()`) — **not** IndexedDB/Firestore.
  - Tag CRUD + CSV export/import (`exportCSV`, `importCSV`, `parseCSVLine`).
  - Shared tag-search-dropdown helper (`setupTagSearch`) reused by both Calculator and Batch tabs.
  - On first load with an empty library, seeds 5 sample tags (see `init()` at the bottom of the file).
- `css/style.css` — all styling.
- `manifest.json` / `sw.js` — PWA install + offline support. `sw.js` is a cache-first service worker; its cache name (`CACHE = 'raw-to-pv-v3'`) must be bumped manually whenever a change needs to force-update already-installed instances on mobile.

This app intentionally does **not** follow the 9-Module IIFE + IndexedDB + Firestore architecture used in other Supasit.A projects — it's a small offline-only single-purpose tool, so plain `localStorage` and a flat script are sufficient here.

## Key quirk: SVL input field

The SVL input (`calc-svl`, `batch-svl`, `modal-svl`) is `type="text" inputmode="decimal"`, not `type="number"`. This was a deliberate fix (see recent commit history) so the minus sign can be typed directly on Samsung keyboards, which otherwise block `-` on numeric inputs. Related pieces that depend on this:
- `parseSVL()` — manually parses the text value, allowing negatives like `-600`.
- `toggleSign()` / the `±` button — flips the sign of whatever's in the field.
- The floating `#minus-bar` — appears above the on-screen keyboard when an SVL field is focused, positioned via `window.visualViewport`.

Do not change these inputs back to `type="number"` without re-checking this Samsung-keyboard regression.

## Running / testing

There is no test framework, linter, or build command in this repo. To work on it:
- Open `index.html` directly in a browser for quick checks.
- To test service-worker/PWA behavior, serve the folder over `http(s)` (e.g. `npx serve .` or `python -m http.server`) — service workers don't register on `file://` origins.

## Deployment

`.github/workflows/deploy.yml` deploys the entire repo root as a static site to GitHub Pages automatically on every push to `main` (via `actions/upload-pages-artifact` + `actions/deploy-pages`). No build step runs — the checked-out files are published as-is.

## Data model

Each tag stored in the library has the shape:

```js
{ id, name, description, svh, svl, unit }
```

`id` is generated by `nextId()` (timestamp + random suffix). CSV export/import uses columns `Tag Name, Description, SVH, SVL, Unit`.
